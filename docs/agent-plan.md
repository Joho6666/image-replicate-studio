# 图片复刻 Agent 方案（草案 2026-11-05）

目标：让通用图像模型（目前是 GPT 2.6 flare，经 JOHO 中转站）加上工具、知识库和 skill 之后，稳定做出"真人质感"的复刻图，并能服务客户（长期客户 + 散单）。

## 1. 先说结论：真实感从哪来

2026-11-05 在客户 A 上实测的排序（真实感由高到低）：

1. **复刻换人（保留真实参考图的背景、光线、姿势，只换人和衣服）**：最真。
2. 复刻换人 + 补光（智能匹配场景光）：脸和背景光更统一，但偏黄偏软，不默认开。
3. 从零生成 + 写实包 v1：可用，但背景和姿势明显"摆拍感"。
4. 从零生成 + 写实包 v2 / 后期「手机原图感 +」：没有测完，用户判断从零生成整体不如复刻换人，已停止投入。

所以 agent 的第一职责不是"把提示词写得更好"，而是**选对路线、找到合适的真实参考图、做完自检**。提示词、知识库、skill 只是减少翻车，管不了模型上限。

缺的有三块：**配方卡的检索**、**自动质检（看图）**、**会做决策的 agent**。

## 3. 目标架构

```
用户 / 客户需求（一句话 + 客户 + 参考图或风格词）
        │
        ▼
   ┌─────────┐  读   ┌──────────────┐
   │  Agent  │◄─────►│  配方知识库   │  配方卡 + 失败案例 + 姿势库
   │ (规划)  │       └──────────────┘
   └────┬────┘
        │ 调用工具（HTTP）
        ▼
   Studio 工具层：复刻换人 / 出图 / 补光 / 实况 / 导出
        │
        ▼
   自动质检（看图模型）──不合格──► 带原因重做一次 ──► 仍不合格列缺额
        │合格
        ▼
   画廊 + 人工挑图 + 客户质检清单 + 导出（带 AI 标识）
```

### 3.1 Agent 的决策（现在由人工判断的部分）

1. **选路线**：有可商用的真实参考图 → 复刻换人；没有 → 从零生成（并提示"质感会差一档"）。
2. **选参数**：模型、后期、是否补光、衣服保留还是更换、姿势。优先沿用配方卡里评分最高的组合。
3. **提交并等待**，读任务状态和错误（被审核拦截时按提示把服装和姿势改保守，只重试一次）。
4. **自检**（见 3.3），不合格时带着具体原因重做，最多一次；仍不合格列为缺额，不无限抽卡。
5. **收尾**：把成功的组合写回配方卡，高星成品留作下次参考。

边界：agent **不绕过审核、不替用户做授权判断、不自动发布**。涉及真人肖像的新用途（比如从静图变成视频、风格变化很大）一律回到"客户是否同意"这一步，由用户确认。

### 3.2 配方知识库

不放教程文字，放**验证过的配方卡**。一张卡的字段：

```jsonc
{
  "id": "recipe-qipao-garden-01",
  "title": "旗袍花园·斑驳阳光",
  "route": "replica_swap",              // replica_swap | from_scratch
  "reference": { "source": "own|licensed|third_party_test_only", "file": "..." },
  "model": "gpt-image-2.6-flare",
  "prompt_fields": { ... },             // 复刻换人的参数 / 出图表单
  "outfit_mode": "change",
  "post": "phone",
  "relight": "none|scene_match",
  "tags": ["国风", "户外", "斑驳光", "半身"],
  "scores": { "likeness": 4, "realism": 4, "client_ok": null },
  "failures": [ { "symptom": "脸偏小", "cause": "全身构图", "fix": "改半身" } ],
  "created": "2026-11-05", "last_used": null
}
```

检索方式（够用即可，不上向量库起步）：
- 按**标签 + 路线**过滤，再按评分排序；
- 给一张新参考图时，用看图模型生成标签（场景、光线、景别、风格词），再匹配；
- 样本超过几百张再考虑向量检索。

另外两份只读资料放进知识库：
- **姿势库**（`lib/poses.mjs`，24 个自写姿势，之后继续扩）；
- **失败案例表**（来自 `docs/realism-research.md` 和 skill 的"已验证的坑"），例如：写雀斑毛孔会满脸斑、吊带加飞吻会被判 sexual、闭眼逆光换脸认不出。

### 3.3 自动质检（最关键，现在缺）

逐张检查，输出每项通过/不通过加原因：

1. **像不像本人**：和客户的脸部参考照对比（身份、发型、痣的位置）。
2. **截屏残留**：有没有按钮、头像、文字、页码。
3. **解剖**：手指数量、肢体比例、头身比。
4. **衣服**：保留模式下是否与参考一致；更换模式下是否与描述一致，是否完全遮盖。
5. **背景**：和参考图是否一致，有没有多出或缺失的大件物体。
6. **敏感度**：是否触及已知会被拦截或我们不做的内容。

实现路径（二选一，先确认哪个可用）：
- 让中转站接一个**看图模型**（最省事，保持一个入口）；
- 修好本机 **vision MCP**（目前连接失败），agent 通过它看图。

没有看图能力之前，自检由人工用对比图完成，agent 只做"出图 + 整理对比图"。

## 4. 分阶段实现

### 阶段 0：把复刻换人跑通（已完成工具，待实测）
- 已做：「⑥ 复刻换人」标签、自动裁截屏、保留/更换衣服、结果进画廊。
- 验收：用客户 A 在表单里跑 3 张不同参考图，裁剪、去界面、像不像都能一次到位；记录失败原因。
- 不确定项：自动裁剪下边在 5/17 张截屏上偏了，需要继续收集样本调规则。

### 阶段 1：配方卡 + 检索（约 1 周）
- 在"风格卡"基础上扩字段（路线、参考来源、评分、失败原因、标签）。
- 复刻换人出图后，一键"存成配方卡"。
- 按标签检索 + 在表单里"套用配方"。
- 验收：做过的 5 个场景（草地、工业风咖啡馆、漫画墙、旗袍花园、街拍）都能存成卡，并能一键复现同样的参数。

### 阶段 2：自动质检（约 1 周，取决于看图模型）
- 先确定看图方案（中转站模型 or vision MCP）。
- 实现 3.3 的 6 项检查，结果写进任务记录，画廊里显示红绿标记。
- 验收：拿已经人工评过的 30 张图跑一遍，和人工判断的一致率；"像不像本人"这一项要单独看误判率。

### 阶段 3：Agent 编排（约 1–2 周）
- 以 skill + 接口调用的方式实现 3.1 的决策循环；可以先用 Claude 本身当 agent，不必另写程序。
- 对话入口：用户说"给客户 A 做一组旗袍写真"，agent 选配方、提交、质检、整理对比图，等用户挑。
- 验收：10 个真实需求，人工干预次数相比现在减少一半以上。

### 阶段 4：按需再做
- 向量检索、姿势组一键出图的联动、客户自助选图、从实况图到短视频。

## 5. 风险与边界

| 风险 | 处理 |
|---|---|
| 参考图是别人的作品 | 配方卡里标明来源；`third_party_test_only` 的卡禁止用于客户交付，导出时提示 |
| 真人肖像的新用途（视频、风格大变） | 回到"客户是否同意"，由用户确认，agent 不自行判断 |
| 内容边界 | 不做情色倾向、校园制服、突出腿脚等造型；被审核拦截时只改保守一次，不绕过 |
| 自动质检误判 | "像不像"始终保留人工最终确认，自检只做初筛 |
| 成本 | 中转站自建，不做成本限制；但单次任务设重试上限，避免失控 |
| 客户数据 | 保留期按档案走，照片只在本机，不进 GitHub |
| 自动模式拦截 | 真人肖像的生成命令在自动模式下会被拦，需要用户在终端运行或在 GUI 里点；agent 不尝试绕过 |

## 6. 需要你决定的事

1. **看图能力走哪条**：让中转站接看图模型，还是修好 vision MCP？
2. **可商用的参考图从哪来**：自己拍、摄影师合作、客户提供，还是有授权的图库？这决定配方卡里 `reference.source` 的主要取值。
3. **agent 放在哪**：继续用 Claude 当 agent（零开发，靠 skill），还是在 Studio 里做一个对话入口（要开发）？建议先用前者验证流程，稳定后再做后者。
